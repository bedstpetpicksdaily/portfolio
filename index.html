System Architecture

160+ modules. One orchestrator.

Benson's autopilot engine runs a sequential cycle of autonomous steps. Each module is independent, error-isolated, and logs every action.

Core

Autopilot Engine

Central orchestrator running 30+ steps per cycle on a 4-hour schedule. Each step is try/catch isolated, so one failure never stops the cycle. Full activity log written to disk on every action.

Content

Niche Content Engine

Per-niche product research via Claude API. Generates SEO-optimized blog posts with structured JSON output, validates format, writes HTML, and pushes to GitHub Pages.

SEO

Indexing Pipeline

Submits new URLs to Google Search Console API and Bing IndexNow on every cycle. Tracks submitted URLs in a dedup log to avoid re-submission. Sitemap auto-rebuilt after each publish.

Reliability

Self-Healing Health Check

Scans all 7 sites every cycle for broken affiliate links, missing meta descriptions, failed pushes, and oversized files. Flags issues to the activity log and auto-fixes what it can.

Revenue

P&L Tracker

Logs monthly revenue and expenses automatically. Reads Amazon Associates CSV exports. Calculates net profit per niche and tracks performance over time.

Growth

Email Capture

Injects niche-specific Mailchimp signup forms into every post via direct POST integration, no backend required. Honeypot spam protection. Tracks injection state per post to avoid duplicates.

LLM

Prompt Architecture

Context-isolated prompts per module, no shared state between tasks. Structured JSON output validation with retry on malformed response. Model routing: Haiku for volume, Sonnet for quality-critical tasks.

Cost

Cost Discipline

Total API + hosting cost: $27/month for 7 sites and 3,300+ posts. Achieved through model routing, prompt token budgeting, batch processing, and caching repeated lookups across cycles.

Case Study

Diagnosing and fixing an AdSense policy violation

Google flagged one site for "Low value content." I treated it as a systemic bug across all 7 sites, not a one-off content edit — and root-caused it instead of patching around it.

What was wrong

A chunk of posts across the network were near-duplicates — same product, same angle, generated on different days. Another chunk were titled as brand-vs-brand comparisons but contained single-brand promotional copy with no real comparison inside.

Diagnosis

Built a clustering pass over ~3,300 posts across all 7 sites — Jaccard similarity over stemmed title tokens, unioned into clusters via union-find — to catch genuine near-duplicates without false-positiving on titles that just shared common phrasing.

Fix

Used an LLM to merge each cluster into one genuinely comparative post — real pros/cons, a real verdict, a real FAQ — instead of deleting duplicates and losing the content. 1,010 clusters merged in total.

Root cause

Fixed the actual prompt in the content generator so posts titled as comparisons are now required to compare real brands. This is the part that stops it recurring — cleanup alone just means doing it again in 3 months.

What the cleanup exposed

Checking my own work surfaced 3 more bugs nobody asked me to find: a hero-image fetcher silently failing on every request for weeks (wrong default header, logged as success), a "related posts" feature that never revalidated links after posts were deleted, and a homepage image regex that missed images whenever an attribute came before src. All shared the same pattern: something marked "done" once, never re-checked.

def run_autopilot_cycle(silent=False):
    actions, errors = [], []

    # Every step is isolated, one failure never kills the cycle
    try:
        from core.skills.niche_manager import run_all_niches
        result = run_all_niches(posts_per_cycle=2)
        if result and "No active" not in result:
            actions.append(result); _log(result)
    except Exception as e:
        errors.append(f"Niche manager: {e}"); _log(f"Error: {e}")

    try:
        from core.skills.google_indexing import submit_new_pages
        result = submit_new_pages(max_urls=10)
        if result and "no new" not in result:
            actions.append(result); _log(result)
    except Exception as e:
        errors.append(f"Indexing: {e}"); _log(f"Error: {e}")
niche_content_engine.py: Claude API product research with dedup
def _ai_product_ideas(niche_focus, count=8, exclude=None):
    # Pass done list so Claude avoids already-published products
    avoid_block = ""
    if exclude:
        sample = list(exclude)[-40:]
        avoid_block = "\n\nDO NOT suggest:\n" + "\n".join(
            f"- {p}" for p in sample
        )

    r = client.messages.create(
        model="claude-haiku-4-5-20251001",
        max_tokens=1200,
        messages=[{"role": "user", "content":
            f"List {count * 4} UNIQUE Amazon products for: {niche_focus}"
            f"\nFormat: Name | search terms | emoji{avoid_block}"
        }]
    )
    # Parse, filter against done list, return only fresh products
    products = _parse_product_list(r.content[0].text)
    return [p for p in products if p["name"].lower() not in exclude]
site_auditor.py: self-healing dead link detection
def audit_all_sites(max_posts_per_site=30):
    results = {}
    for niche, site_dir in NICHE_DIRS.items():
        posts = list((site_dir / "blog").glob("*.html"))
        for post in posts[:max_posts_per_site]:
            soup = BeautifulSoup(post.read_text(), "html.parser")
            for a in soup.find_all("a", href=True):
                if "amazon.com" in a["href"]:
                    status = _check_url(a["href"])
                    if status == "dead":
                        # Auto-replace with search URL using affiliate tag
                        _replace_dead_link(post, a["href"], niche)
                        results[str(post)].append("fixed")
    return results

What Benson actually does

Skip the jargon. Here's the same project explained the way I'd explain it to someone who isn't technical.

Normally, running seven websites well takes a small team. Someone writing content, someone doing SEO, someone managing links, someone watching for things breaking. That's a lot of people and a lot of cost.

Benson does that team's job by itself. Every four hours it wakes up, figures out what content is needed, writes it, checks its own work, publishes it, tells search engines it exists, fixes anything that broke last cycle, and goes back to sleep. I don't log in and tell it what to do, and I don't review every post before it goes live. I built the checks so I don't have to.

What I'm proudest of isn't the AI writing content. It's that I built something that runs on its own, with no formal training, no team, and about the cost of a phone bill a month. That's the same underlying skill as building a good tool for an organization where one person is already doing five jobs.
